# Омниканальная поддержка клиентов «Командир»

Единый скилл на весь финальный проект курса «Практический курс по вайб-кодингу
на Claude Code». Описывает, как устроена и как эксплуатируется система из
четырёх частей — см. общую схему в [корневом README](../../../README.md).

## Компоненты

1. **`telegram-bot/`** — Telegram-бот (Telegraf), ведёт клиента по сценарию
   регистрации/заказа на сайте, пробрасывает «застрявших» на менеджера.
2. **`max-bot/`** — то же самое для MAX (`@maxhub/max-bot-api`), независимая
   копия сценария.
3. **`abcp-max-bridge/`** — дублирует уведомления о заказах из ABCP
   (Telegram-группа) в MAX. В проде — готовый бот `@MaxTelegramBridgeBot`,
   `telegram_to_max_bridge.py` — собственная reference-реализация той же схемы.
4. **Коннектор к ABCP** (ниже и в скилле `publish-bot-to-site`) — публикует
   кнопку бота на сайте, так как у ABCP нет публичного API для контента.

## Типовые задачи и как их решать

### Завести такого же бота для другого сайта на ABCP

1. Склонируй `telegram-bot/` (или `max-bot/`) как основу.
2. Пройди сайт-клона вручную и перепиши граф шагов в `src/steps.js` под его
   реальный интерфейс (подписи полей, порядок экранов регистрации/корзины —
   сценарий жёстко завязан на конкретный сайт, он не угадывается заранее).
3. Получи токен: Telegram — через @BotFather; MAX — через dev.max.ru, затем
   зарегистрируй в кабинете business.max.ru (нужен верифицированный профиль
   организации).
4. Заполни `.env` по `.env.example`, подними процесс под pm2.

### Изменить/починить шаг сценария

Правь узлы графа в `src/steps.js` (`type: 'instruction' | 'choice' | 'end'`,
связи через `next`/`options[].next`). У Telegram- и MAX-версий это отдельные
копии файла — правку синхронизировать руками в обеих.

### Понять, где клиенты чаще всего застревают

`data/events.jsonl` и `data/stuck-log.jsonl` в папке каждого бота — журнал
шагов и отказов. Разбор ведёт отдельный скрипт `bot_stats.py` (не входит в
этот репозиторий, см. корневой README).

### Настроить пересылку заявок менеджеру и ответ без поиска клиента

`MANAGER_CHAT_ID` (Telegram) / `MANAGER_CHAT_ID` или `MANAGER_USER_ID` (MAX)
в `.env`. Менеджер отвечает нативным «Ответить» на пересланное сообщение —
бот сам находит клиента по chat_id/user_id, привязка хранится в памяти
процесса (до 500 последних заявок, не переживает перезапуск). Разовый ответ
после перезапуска — `node reply-to-client.js <id> "текст"` в папке бота.

### Продублировать уведомления о заказах ABCP в другой мессенджер

Схема моста: ABCP уже умеет слать уведомления в Telegram-группу — остаётся
только слушать её и пересылать дальше. Проще всего добавить в эту группу
готового бота-мост (как `@MaxTelegramBridgeBot` для MAX), не разворачивая
свой код; если готового решения для нужного мессенджера нет — за основу
можно взять `abcp-max-bridge/telegram_to_max_bridge.py`.

### Опубликовать/обновить кнопку бота на сайте (коннектор к ABCP)

У ABCP нет публичного API для контента/виджетов сайта — кнопка публикуется
через браузерную автоматизацию панели `cp.abcp.ru` (инфоблок `bodyScripts`).
Полный пошаговый порядок, включая защиту от конфликтов с существующими
виджетами и обход анти-бот блокировки — в скилле
[`publish-bot-to-site`](../publish-bot-to-site/SKILL.md).
