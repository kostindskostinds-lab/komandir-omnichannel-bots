# komandir-telegram-bot

Telegram-бот-инструктор: пошагово ведёт пользователя через регистрацию и оформление
заказа на **komandir-nn.ru** (интернет-магазин автозапчастей на платформе ABCP).

На каждом шаге бот показывает инструкцию и кнопки **✅ Получилось** / **❌ Не получилось**.
Если не получилось — бот даёт подсказку по этому конкретному шагу, а если и это не
помогло — пересылает вопрос живому менеджеру в Telegram (или показывает телефон/почту).

Сценарий (`src/steps.js`) написан по реальному интерфейсу сайта: подписи полей формы
регистрации, порядок экранов корзины и оформления заказа проверены вручную на живом сайте.
Приоритет — как на самом сайте: вход/регистрация предлагаются в первую очередь,
«оформить заказ без регистрации» — только как запасной вариант, если войти не получается.

## Установка

1. Установите Node.js 18+.
2. В этой папке выполните:
   ```
   npm install
   ```
3. Скопируйте `.env.example` в `.env` и заполните:
   - `BOT_TOKEN` — получить у [@BotFather](https://t.me/BotFather) командой `/newbot`.
   - `MANAGER_CHAT_ID` — chat_id менеджера/группы поддержки, куда бот будет слать
     сообщения о застрявших пользователях. Чтобы узнать chat_id — напишите
     [@userinfobot](https://t.me/userinfobot) в Telegram, он пришлёт ваш `Id`.
     Если оставить пустым — бот просто покажет пользователю телефон и почту вместо
     пересылки менеджеру.
   - `COMPANY_PHONE`, `COMPANY_PHONE_2`, `COMPANY_EMAIL` — запасные контакты (уже
     заполнены реальными данными магазина на Кащенко, 6г, можно поменять).
4. Запуск:
   ```
   npm start
   ```
   Бот работает через long polling — отдельный сервер/домен не нужен, достаточно,
   чтобы процесс `node src/bot.js` был запущен (на вашем компьютере, VPS, или через
   pm2/systemd для постоянной работы).

## Команды бота

- `/start` — начать сценарий сначала (спросит, есть ли уже аккаунт).
- `/order` — сразу перейти к оформлению заказа (для тех, у кого аккаунт уже есть).
- `/help` — краткая справка и контакты магазина.

## Ссылка после регистрации (предложение помощи)

Бот не может написать клиенту первым — он пишет только тем, кто сам открыл чат.
Поэтому после регистрации на сайте клиенту даётся ссылка на бота с параметром:

    https://t.me/komandirnn_bot?start=registered

(ссылку разместить в письме о регистрации и на странице «Спасибо» в панели ABCP).
Клиент нажимает «Начать» — бот присылает приветствие `welcome_registered`
(steps.js) с кнопками: помощь с подбором (заявка уходит в MANAGER_CHAT_ID, как и
«Вопрос менеджеру»), пошаговое оформление заказа, вопрос менеджеру, «пока не нужно».
Без параметра `?start=registered` бот показывает обычное приветствие.
В журнале `data/events.jsonl` у события `start` есть поле `payload` —
по нему видно, сколько человек пришло по ссылке из письма.

## Помощь менеджера: телефон и ответ прямо в чате

Когда пользователь застревает на шаге (❌ «Не получилось» → 🙋 «Всё ещё не получается —
позвать менеджера»), бот сначала предлагает поделиться телефоном — нативной кнопкой
«📞 Отправить номер» (запрашивает подтверждённый номер аккаунта, без ручного ввода).
Можно пропустить и просто написать вопрос текстом — это не блокирует отправку.
Для обычных «просто вопрос менеджеру» (через меню, без ❌) телефон не запрашивается —
осознанный выбор, чтобы не создавать трение там, где человек хочет просто что-то узнать.

**Менеджер отвечает клиенту без поиска по id.** На пересланную в MANAGER_CHAT_ID заявку
менеджер отвечает через нативное Telegram-«Ответить» (reply) на это же сообщение —
бот сам находит нужного клиента по chat_id, привязанному к сообщению, и пересылает
ответ. Никаких прав/настроек для этого в Telegram не нужно: ответ на сообщение бота
доставляется ему всегда, даже без админских прав в группе (в отличие от MAX, см. README
`komandir-max-bot`). Работает только для группового `MANAGER_CHAT_ID`, не для личных
сообщений одному менеджеру. Привязка «сообщение → клиент» хранится в памяти процесса
(до 500 последних заявок), не переживает перезапуск бота.

**Разовый ответ клиенту без чата** (если заявка старая и её `message_id` уже не отслеживается,
либо после перезапуска бота): `node reply-to-client.js <chat_id> "текст"` — отправляет
сообщение по chat_id напрямую через Bot API, не трогая живой процесс. chat_id берите из
самой заявки, строка «Пользователь: Имя (id …)».

## Как редактировать сценарий

Весь текст шагов и подсказок лежит в `src/steps.js` — это граф узлов:

- `type: 'instruction'` — шаг с кнопками ✅/❌. Поля: `text` (инструкция), `tip`
  (подсказка при ❌), `next` (id следующего шага), опционально `extraFailOption`
  (доп. кнопка-развилка при ❌, например переход на гостевой заказ).
- `type: 'choice'` — развилка без ✅/❌, пользователь сразу выбирает один из
  `options: [{ label, next }]`.
- `type: 'end'` — финальный экран, тоже со списком `options` (например, начать заново).

Чтобы поменять формулировку или добавить шаг — правьте/добавляйте записи в объекте
`STEPS`, ссылаясь друг на друга через `next`/`options[].next` по `id`.

## Данные

- `data/state.json` — последний шаг каждого пользователя (переживает перезапуск бота).
- `data/stuck-log.jsonl` — лог того, на каких шагах люди чаще всего нажимают
  «Не получилось» — полезно, чтобы понять, где сайт неудобен, и упростить эти места.
- `data/events.jsonl` — журнал всех событий (старт, шаги, ✅/❌, вопросы менеджеру,
  телефоны, ответы менеджера) для статистики. Разбор: `python ../bot_stats.py`
  (или `--bot telegram`, `--days N`) — воронка по шагам, доля дошедших до конца,
  сколько вопросов доставлено и отвечено.

Обе папки не попадают в git (см. `.gitignore`).

## Что бот НЕ делает (сознательно)

- Не логинится и не отправляет заказ за пользователя — только показывает, что нажать.
- Не хранит и не запрашивает пароли пользователя.
- Не использует ABCP API "под капотом" — сайт уже открывается пользователем в обычном
  браузере, бот лишь дублирует инструкцию рядом в Telegram.
